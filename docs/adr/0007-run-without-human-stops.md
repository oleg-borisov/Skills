# Запуск без остановок на человека

rr-loop ждал явной авторизации merge в Done, rr-cascade-loop-fast и rr-parallel-loop — ещё и подтверждения плана перед первым исполнителем, а решения по MINOR требовали отдельной остановки перед финальной проверкой. На обычном пути эти остановки не меняют результат и только добавляют к времени запуска ожидание человека. Теперь сам вызов навыка считается согласием на завершающие действия, а план человеку показывается без ожидания подтверждения.

- Согласие покрывает merge в цель при quality GREEN и чистом rebase, tracker completion и удаление созданных запуском worktrees. Отказ задаётся словами в аргументах запуска.
- Цель merge фиксируется при создании журнала запуска: из аргументов либо как ветка, от которой контроллер сам создал task-ветку. Если запуск начат уже на task-ветке и цель не названа, контроллер задаёт один вопрос до первого исполнителя.
- Push и перевод PR в ready выполняются, только когда их требует repo workflow или трекер. Слияние PR остаётся за человеком или CI.
- План каскада и граф параллельного запуска, включая области записи и число исполнителей, контроллер выводит из готовых задач и показывает первым сообщением. Нарезку человек согласовал при создании задач. Циклы, неизвестные связи и конфликт источников по-прежнему останавливают запуск.
- MINOR исправляются сразу в пределах лимита итераций; остаток попадает в итог запуска без остановки.
- Неясная спецификация, включая отсутствие согласованных test seams, по-прежнему требует вопросов человеку до первого исполнителя. Конфликт rebase, исчерпанные лимиты и критичные замечания без прогресса останавливают запуск, как раньше.

Цена решения — merge без того, чтобы человек увидел результат: качество запуска опирается на обе оси ревью и финальную проверку.

Заменяет подтверждение запуска из [ADR-0002](0002-rr-cascade-loop-fast.md) и требование явной авторизации merge в rr-loop, rr-cascade-loop-fast и completion rr-parallel-loop. Остальное в ADR-0002 и [ADR-0005](0005-final-gate-after-review.md) сохраняется.

## Considered Options

- Один блокирующий вопрос до первого исполнителя: отклонено — запуск должен начинать работу сразу.
- Вопрос первым сообщением без ожидания ответа: отклонено — без ответа запуск всё равно встаёт в Done.
