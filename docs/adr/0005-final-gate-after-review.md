# Полный gate после review

Retro запуска SPO-559 (codex://threads/01a1447d-466c-7480-aeae-509939623f62) выявило повторные полные проверки до обнаружения контрактных дефектов на review. Согласованный подход: workers выполняют targeted checks с исправлением ошибок в своей фазе; независимый verifier выполняет полный gate после разрешения review findings и решений человека. Ожидаемый выигрыш — меньше полных прогонов между исправлениями review; цена — более позднее обнаружение интеграционных регрессий. Ускорение пока не измерено.

## Согласованные границы

- В rr-loop gate относится к итоговому результату одной задачи; в rr-cascade-loop-fast и rr-parallel-loop — всего согласованного плана. Промежуточные результаты разблокируют следующие задачи без объявления итогового QUALITY = GREEN.
- Частота review сохраняет различия workflow: каскад использует промежуточные и покрывающие review с переносом findings; parallel проверяет собранный результат после интеграции всех задач.
- RED исправляется существующим механизмом worker repair по единому failure inventory. После targeted checks и нового commit выполняются обязательный review исправления и triage, затем повторный полный gate. Смена порядка не отменяет обязательные проверки.
- Контракты targeted checks остаются у implementer/reviser; отдельный controller-механизм локальных исправлений не вводится.
- Итоговые gate evidence и review coverage должны покрывать один финальный HEAD. Исторические targeted checks отдельных задач сохраняют SHA своих handoffs.
- Для deferred:batch каскада требование полного GREEN с первой попытки заменяется успешными targeted checks worker. Остальные ограничения размера, scope, количества отложенных задач и обязательного review при carried findings/active critical сохраняются.
- После изменения HEAD при merge reconciliation выполняются обязательный review, triage и полный gate. Неизменный HEAD с актуальным evidence повторных проверок не требует.
- Пропуск Standards review допустим только при уже подтверждённом автоматическом покрытии применимых правил либо доказанном отсутствии документированных правил. Будущие проверки финального gate не являются основанием для пропуска.
- Обратная совместимость со старыми запусками не требуется: считаем, что незавершённых запусков прежнего workflow нет. Миграция ledger и версионирование checkpoint для этого изменения не вводятся.
- Финальное закрытие задач и COMPLETED остаются после подтверждённого merge и согласованных completion actions. Покрытие review промежуточного результата само по себе не означает итоговый GREEN.

Этот ADR заменяет требование полного gate каждого тикета из ADR-0002 и отказ от объединения verifier-прогонов вместе с условием GREEN первой попытки из ADR-0003. Остальные решения этих ADR сохраняются. Канонический порядок исполнения определён в трёх SKILL.md; ADR объясняет выбор, не заменяет controller-контракты.
