# Каскадная реализация задач спецификации

Навык `rr-cascade-loop` основан на действующем `rr-loop` с точечными изменениями проверенных формулировок. Базовый навык сохраняет своё поведение. Решения ниже согласованы при проектировании.

Каскад выполняется в одной текущей ветке, с коммитами отдельных фаз и одним финальным merge. Завершение тикетов происходит после интеграции. До запуска человек подтверждает название спецификации, набор задач и порядок исполнения.

Спецификация или обычная задача без готовой нарезки передаётся обычному `rr-loop`. Спецификация с готовыми тикетами исполняется по этим тикетам. Если ссылка на трекер указывает на спецификацию, в план входят её незавершённые подзадачи. Controller самостоятельно не выполняет декомпозицию и не вызывает `to-tickets`. Семантика связей трекера определяется документом целевого репозитория `docs/agents/issue-tracker.md`. Наличие блокера у первой задачи останавливает запуск.

Внутренняя зависимость удовлетворяется прохождением предыдущего шага каскада по ledger, включая допустимый перенос проверки исправлений: закрытия тикета в трекере ждать не требуется. Внешние блокеры проверяются перед каждой активацией; обнаруженный блокер останавливает каскад. Внешние задачи автоматически в план не добавляются.

Если невозможно достоверно определить подзадачи, завершённость или направление блокирующей связи, планирование останавливается с конкретной причиной. `Tracker activation = NOT_APPLICABLE` не позволяет обходить проверку зависимостей. При отсутствии подзадач используется обычный `rr-loop`; если подзадачи есть, но все завершены, запуск заканчивается без workers с сообщением об отсутствии задач для каскада.

Совместимые ограничения порядка объединяются; конфликт источников или цикл зависимостей требует решения человека до запуска. Для независимых задач используется порядок спецификации, затем стабильный порядок по ID/пути.

После промежуточного Revise отдельный delta-review пропускается: каскад переходит к активации и Implement следующей задачи. Следующий Implement получает оставшиеся findings как обязательную часть scope вместе с текущей задачей, в том числе при неисправленном critical finding или unchanged HEAD reviser. Он устраняет проблемы предыдущего шага, чтобы pre-review gate и Review получили согласованный результат. Это осознанное объединение проверок ради сокращения числа вызовов leaf-agents. Явный отказ человека исправлять critical finding или противоречие требований, требующее решения человека, останавливает переход.

На каждом новом шаге Review запускает обе оси от их `last_reviewed_head`, проверяя изменения текущей задачи и перенесённые замечания. Требования будущих задач не считаются отсутствующей функциональностью. На последней задаче spec-reviewer дополнительно проверяет покрытие всей спецификации, а Decide / Revise и Human decisions работают как в базовом цикле.

Green pre-review gate обязателен после каждой задачи. Если готовый план явно допускает red между задачами и обещает green только в конце, каскад останавливается до запуска с сообщением о несовместимости плана. Пропуск промежуточного delta-review после Revise не отменяет gate перед совмещённым Review следующего шага.

MINOR и обычные human items накапливаются до финального Human decisions. Дешёвые MINOR исправляются попутно по правилам базового цикла. Устранённые замечания закрываются по результату проверки; дубликаты MINOR объединяются с сохранением исходных ID и истории. Человек получает актуальные оставшиеся замечания. Неразрешимое противоречие или отказ исправлять BLOCKER требует немедленного Human attention. Лимит четырёх critical review iterations считается отдельно для каждой задачи; повтор одного finding без прогресса отслеживается сквозь весь каскад с сохранением его ID.

Ledger сохраняет подтверждённый снимок плана, источники с версиями/хешами, зависимости, порядок, текущую задачу, fixed points, результаты фаз и непроверенные исправления. Recovery сверяет снимок с Git и источниками. Изменение состава задач, требований или порядка требует подтверждения обновлённого плана; завершённые фазы повторно не запускаются.
