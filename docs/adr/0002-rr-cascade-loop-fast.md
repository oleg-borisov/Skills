# Исправление замечаний в следующей задаче

В `rr-cascade-loop-fast` после промежуточного Review controller передаёт findings следующему implementer без промежуточных Decide / Revise. Implementer совмещает исправления с реализацией следующего тикета; после green pre-review gate обе оси Review проверяют текущую задачу и предыдущие findings. После Review последнего тикета выполняется обычное продолжение `rr-loop`.

Такой порядок исключает отдельный reviser для замечаний промежуточной задачи. Цена — следующая задача начинает работу поверх известных дефектов. BLOCKER/MAJOR и согласованные FIX_NOW обязательны к исправлению; остальные findings передаются для контекста. Дешёвые MINOR разрешены попутно при исправлении critical по прежним ограничениям, остальные остаются до финального решения человека. Повтор critical без прогресса сквозь задачи, неразрешимое противоречие или отказ человека сохраняют правила остановки.

Планирование, подтверждение запуска, проверки внешних блокеров, одна ветка, финальный merge и recovery сохраняются из каскада. Ledger хранит план, текущую задачу, stable finding IDs, dispositions и fixed points обеих осей. Green gate обязателен после каждого Implement; red исправляется до Review, без перехода к следующему тикету. Без готовой нарезки используется обычный `rr-loop`.

Новый навык самостоятельный, с точечными отличиями от проверенного текста `rr-loop`; существующие навыки и leaf-agents сохраняются. Промежуточная последовательность — Implement → Verify → Review, а не буквальный вызов `/implement` из leaf-agent: workers остаются прямыми детьми primary и коммитят до проверки controller.
