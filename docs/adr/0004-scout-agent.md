# Exploration-агент scout

Во всех трёх rr workflows scout запускается однократно до первого worker, когда есть конкретные исследовательские вопросы, общие для нескольких последующих workers. Локальное исследование одной задачи остаётся у implementer: отдельный scout в этом случае может лишь повторить чтение.

Заметки находятся в notes_dir под каталогом запуска (LEDGER_DIR), вне отслеживаемых Git файлов, и содержат source_head, relevant_paths и evidence. Workers получают только relevant paths заметок и сверяют изменившиеся sources с кодом. Недоступность scout или notes_dir даёт NOT_APPLICABLE, а не BLOCKED.

Named-контракт сохраняет переносимость профилей хостов. Повторное использование общих результатов должно окупать отдельный вызов scout; сам факт неизвестных conventions не является достаточным основанием для него.
