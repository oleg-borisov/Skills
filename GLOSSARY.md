# RR workflows

Термины циклов реализации и проверки задач по спецификации.

## Language

**Быстрый каскад (rr-cascade-loop-fast)**:
Последовательная реализация задач, в которой исправление замечаний промежуточного review входит в реализацию следующей задачи. Обычный цикл Decide / Revise начинается после review последней задачи.

**Текущая задача каскада**:
Задача из согласованной последовательности, которую каскад реализует на текущем шаге.

**Последняя задача каскада**:
Завершающая задача согласованной последовательности, после которой каскад проходит обычный цикл Decide / Revise и Human decisions.

**План каскада**:
Подтверждённый человеком набор готовых задач и порядок их исполнения с зависимостями и исходной спецификацией. Задача без готовой нарезки исполняется обычным `rr-loop`.

**Перенесённое замечание**:
Замечание предыдущего шага каскада, исправление которого входит в Implement следующей задачи, а подтверждение — в её Review.

**Документационная задача**:
Задача, изменяющая только неисполняемый документальный текст. Исполняемые примеры, конфигурация и инструкции агентов к этой категории не относятся.

**Scout**:
Опциональный exploration-агент rr-loop и каскада, исследующий конкретные вопросы, общие для нескольких последующих workers; код и checks не трогает.

**Заметки exploration**:
Файлы заметок scout'а в notes_dir вне репозитория; workers получают пути, не содержимое.

**Отложенное ревью**:
Review задачи выполняется не в её собственной фазе, а покрывающим Review. Причины: документационная задача (deferred) или малый diff кодовой задачи (deferred:batch).

**Покрывающее Review**:
Review, проверяющее накопленный diff нескольких задач от fixed point оси до текущего HEAD.
_Avoid_: make-up Review, Review следующей задачи

**Fixed point**:
SHA, от которого соответствующая ось ревьюит diff; для ни разу не ревьюившейся оси — BASE.
