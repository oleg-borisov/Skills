# Индексация покрытия codebase-memory

Скилл доводит **покрытие** графа codebase-memory: после прогона каждый git-репозиторий в целевом каталоге либо уже проиндексирован, либо добавлен в `full`, либо пропущен с задокументированной причиной.

## Шаги

**1. Целевой каталог.** Взять путь из запроса; если не указан — спросить у пользователя.
Критерий: путь абсолютный и существует (`Test-Path -LiteralPath`).

**2. Обнаружение репозиториев.** Найти все каталоги с `.git` рекурсивно (команда в Reference). Отсортировать по глубине пути и отбросить вложенные — репозиторий внутри другого репозитория (вендор/пакеты, напр. ComfyUI в StabilityMatrix); пометить их как пропущенные с причиной «вложенный».
Критерий: каждый верхнеуровневый репозиторий каталога учтён, каждый вложенный явно помечен.

**3. Сопоставление с индексом.** Вызвать `list_projects` — множество `root_path` проиндексированных проектов. Репозиторий проиндексирован, если его путь совпадает с `root_path` проекта (нормализация: нижний регистр, `/`-разделители). `index_status` режим индекса не сообщает — наличие проверять только через `list_projects`.
Критерий: для каждого обнаруженного репозитория известно — есть он в графе или нет.

**4. Добавление отсутствующих.** Для каждого не проиндексированного — `index_repository(repo_path=<путь>, mode="full")`. Вызовы независимы — запускать батчами по несколько параллельно. Ошибки индексации фиксировать в отчёте.
Критерий: каждый отсутствующий репозиторий либо вернул `status: "indexed"`, либо имеет зафиксированную в отчёте ошибку.

**5. Отчёт.** Вывести список добавленных репозиториев: путь, число узлов и рёбер из ответа (поля `nodes`, `edges`); отдельно — количество уже проиндексированных и пропущенных с причиной.
Критерий: отчёт перечисляет каждый добавленный репозиторий поимённо, не только общее число.

## Ветка: полное покрытие в full

Если запрос «всё в full» / «переиндексируй всё» — шаг 4 заменяется на переиндексацию **каждого** обнаруженного репозитория (включая уже проиндексированные) с `mode="full"`. Так как режим текущего индекса не проверяется, единственный способ гарантировать full — переиндексировать. Уже проиндексированные попадают в отчёт как «переиндексированы в full».

## Reference

**Обнаружение репозиториев** (PowerShell):

```powershell
Get-ChildItem -Path <dir> -Directory -Recurse -Force -ErrorAction SilentlyContinue |
  Where-Object { $_.Name -eq '.git' -and $_.Attributes -match 'Hidden' } |
  ForEach-Object { $_.Parent.FullName }
```

**Вложенность:** репозиторий R вложен, если путь другого найденного репозитория — строгий префикс пути R. Проверять по отфильтрованному списку, отсортированному по глубине.

**Сопоставление:** `list_projects` возвращает `name` и `root_path`; `name` — слаг пути (напр. `D-dev-hdp-achievements`). Сверять по `root_path`, не по имени.
